Why Go? Philosophy & where it shines

In one line: Go was created at Google (2009, by Robert Griesemer, Rob Pike and Ken Thompson) to make large teams productive on large networked systems: it compiles fast, is simple to read, has concurrency built in, and ships as a single static binary.

Design choiceWhat it gives you
Small language (25 keywords)Anyone can read anyone's code. Code reviews are about logic, not cleverness.
Fast compilation, static binariesBuilds in seconds, tiny containers (FROM scratch), no runtime to install.
Goroutines + channelsHundreds of thousands of concurrent tasks cheaply, which is ideal for servers.
Garbage collector tuned for low latencyMemory safety without manual frees, with sub-millisecond pauses.
Powerful standard libraryHTTP server and client, JSON, crypto, TLS, testing, profiling, all built in.
gofmt and a strong toolchainOne code style, built-in testing, race detector, profiler, and dependency management.
Interfaces satisfied implicitlyDecoupling without inheritance hierarchies.

Who uses Go for what

  • Cloud infrastructure: Docker, Kubernetes, Terraform, Prometheus, etcd, Istio and Grafana are written in Go.
  • Backend services and microservices: Google, Uber, Netflix, Monzo, Cloudflare, Twitch, PayPal, Swiggy, Zomato…
  • CLIs and DevOps tools: gh, Hugo, k9s, Caddy.
  • Networking and proxies: high-throughput gateways, load balancers, streaming servers.
⚠️ Where Go is not the best choice

Hard real-time systems or the most extreme low-latency work (C, C++, Rust), heavy numeric and data-science work (Python), GUI desktop apps, and very type-heavy domain modelling where you'd want algebraic data types. For networked backends, Go is one of the best tools available.

The Go proverbs worth memorizing

  • "Don't communicate by sharing memory; share memory by communicating."
  • "Clear is better than clever."
  • "Errors are values."
  • "The bigger the interface, the weaker the abstraction."
  • "Make the zero value useful."
  • "A little copying is better than a little dependency."

The Go syntax cheat sheet

All of the core syntax in one place. Each line is explained in the lessons that follow.

package main

import (
	"errors"
	"fmt"
	"strings"
)

type Shape interface{ Area() float64 }             // interface
type Rect struct{ W, H float64 }                   // struct
func (r Rect) Area() float64 { return r.W * r.H }  // method (value receiver)

type Status int                                    // custom type + enum via iota
const (
	Pending Status = iota // 0
	Paid                  // 1
	Shipped               // 2
)

var ErrNotFound = errors.New("not found")          // sentinel error

func find(m map[string]int, k string) (int, error) { // multiple returns
	v, ok := m[k]                                    // comma-ok idiom
	if !ok {
		return 0, fmt.Errorf("find %q: %w", k, ErrNotFound) // wrap the error
	}
	return v, nil
}

func Map[T, U any](xs []T, f func(T) U) []U {      // generics
	out := make([]U, 0, len(xs))
	for _, x := range xs {
		out = append(out, f(x))
	}
	return out
}

func main() {
	x := 42                                // short declaration
	var y float64 = 3.5                    // explicit type
	s := []int{1, 2, 3}                    // slice
	s = append(s, 4)
	m := map[string]int{"a": 1}            // map
	p := &Rect{W: 2, H: 3}                 // pointer to struct
	var sh Shape = p                       // interface value (pointer has the method too)

	for i := range 3 {                     // range over int (Go 1.22+)
		fmt.Print(i, " ")
	}
	fmt.Println()

	switch {                               // tagless switch
	case x > 40:
		fmt.Println("big")
	default:
		fmt.Println("small")
	}

	if _, err := find(m, "zzz"); errors.Is(err, ErrNotFound) {
		fmt.Println("error:", err)
	}

	ch := make(chan string, 1)             // channel
	go func() { ch <- "from goroutine" }() // goroutine
	fmt.Println(<-ch)

	defer fmt.Println("deferred: runs last")
	fmt.Println(y, s, sh.Area(), Paid, strings.ToUpper("go"),
		Map(s, func(n int) string { return fmt.Sprint(n * n) }))
}

Declaring variables

package main

import "fmt"

var appName = "shop" // package-level: var (never :=)

func main() {
	var a int        // zero value: 0
	var b string     // ""
	var c bool       // false
	var d *int       // nil
	var e []int      // nil slice (len 0, works with append)
	var f map[string]int // nil map: reading OK, WRITING PANICS

	x := 10          // short declaration: only inside functions, type inferred
	y, z := 1, "two" // several at once
	x, w := 20, 3.14 // := needs at least ONE new variable on the left (w is new)

	const pi = 3.14159 // compile-time constant (untyped: precise until used)

	fmt.Println(a, b, c, d, e, f, x, y, z, w, pi, appName)
	fmt.Printf("%T %T %T\n", x, w, z) // int float64 string
}
Zero values: "make the zero value useful"

Every variable is initialized: numbers to 0, strings to "", bools to false, and pointers, slices, maps, channels, functions and interfaces to nil. There is no "undefined". Well-designed Go types (like sync.Mutex, bytes.Buffer) are ready to use at their zero value.

Control flow: if, for, switch, labels

package main

import (
	"fmt"
	"os"
)

func main() {
	// if with a short statement: err is scoped to the if/else
	if f, err := os.Open("missing.txt"); err != nil {
		fmt.Println("open failed:", err)
	} else {
		defer f.Close()
	}

	// for is Go's ONLY loop keyword, in 5 forms
	for i := 0; i < 3; i++ { // classic
		fmt.Print(i)
	}
	fmt.Println()
	n := 0
	for n < 3 { // "while"
		n++
	}
	for { // infinite: exit with break/return
		n++
		if n > 5 {
			break
		}
	}
	for i := range 3 { // range over an integer (Go 1.22+)
		fmt.Print(i)
	}
	fmt.Println()
	for i, v := range []string{"a", "b"} { // range over a slice: index, copy of the value
		fmt.Print(i, v, " ")
	}
	for k, v := range map[string]int{"x": 1} { // map: RANDOM order each run
		fmt.Print(k, v, " ")
	}
	for i, r := range "héllo" { // string: byte index + rune (decodes UTF-8)
		fmt.Print(i, ":", string(r), " ")
	}
	fmt.Println()

	// switch: no fallthrough by default, no break needed
	day := "sat"
	switch day {
	case "sat", "sun":
		fmt.Println("weekend")
	default:
		fmt.Println("weekday")
	}
	// tagless switch = a cleaner if/else-if chain
	score := 82
	switch {
	case score >= 90:
		fmt.Println("A")
	case score >= 80:
		fmt.Println("B")
		fallthrough // explicitly continue into the next case (rarely used)
	case score >= 70:
		fmt.Println("at least C")
	}

	// labels: break out of nested loops
outer:
	for i := range 3 {
		for j := range 3 {
			if i*j == 2 {
				fmt.Println("found", i, j)
				break outer
			}
		}
	}
}
⚠️ Loop variables before Go 1.22

Before Go 1.22, a loop variable was shared by all iterations, so goroutines and closures that captured it all saw the last value. Since Go 1.22 (with go 1.22+ in go.mod) each iteration gets its own variable. You'll still see v := v in older code. That's why.

Functions, closures, defer, panic & recover

package main

import (
	"errors"
	"fmt"
	"strings"
)

// multiple return values: (result, error) is THE Go idiom
func divide(a, b float64) (float64, error) {
	if b == 0 {
		return 0, errors.New("division by zero")
	}
	return a / b, nil
}

// named results: documentation + they can be set by deferred functions
func split(sum int) (x, y int) {
	x = sum * 4 / 9
	y = sum - x
	return // "naked" return: use only in very short functions
}

// variadic
func join(sep string, parts ...string) string {
	return strings.Join(parts, sep)
}

// functions are values: they can be parameters…
func apply(nums []int, f func(int) int) []int {
	out := make([]int, len(nums))
	for i, n := range nums {
		out[i] = f(n)
	}
	return out
}

// …and return values. A closure captures variables from its surrounding scope.
func counter() func() int {
	count := 0
	return func() int {
		count++ // the closure keeps count alive between calls
		return count
	}
}

func main() {
	if q, err := divide(10, 0); err != nil {
		fmt.Println("error:", err)
	} else {
		fmt.Println(q)
	}
	fmt.Println(split(17))
	fmt.Println(join("-", "a", "b", "c"))
	words := []string{"x", "y"}
	fmt.Println(join("+", words...)) // spread a slice into variadic args
	fmt.Println(apply([]int{1, 2, 3}, func(n int) int { return n * 10 }))

	next := counter()
	next()
	next()
	fmt.Println(next()) // 3

	deferDemo()
	fmt.Println(safeDivide(1, 0))
}

// defer: runs when the surrounding FUNCTION returns, in LIFO order.
// The arguments are evaluated immediately, at the defer statement.
func deferDemo() {
	for i := range 3 {
		defer fmt.Println("deferred", i) // prints 2, 1, 0
	}
	fmt.Println("body done")
}

// panic/recover: only for truly unrecoverable situations or programmer bugs.
// recover works only inside a deferred function.
func safeDivide(a, b int) (result int, err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("recovered: %v", r) // set the named result
		}
	}()
	return a / b, nil // integer division by zero panics
}

  • defer inside a loop runs at function end, not iteration end. In long loops, extract a helper function, or you'll keep thousands of files open.
  • Don't use panic for normal errors. Libraries should return errors; panic is for "this should never happen" (and Must* helpers at startup).

Arrays, slices, maps & strings, including the internals

Arrays vs slices

An array has a fixed size that's part of its type ([3]int ≠ [4]int), and it's copied on assignment. A slice is a small header {pointer, len, cap} pointing into a backing array. You'll use slices 99% of the time.

package main

import (
	"fmt"
	"slices"
)

func main() {
	s := make([]int, 0, 4) // len 0, cap 4: pre-size when you know roughly how many
	for i := range 6 {
		s = append(s, i) // when cap is exceeded, append allocates a bigger array and COPIES
		fmt.Printf("len=%d cap=%d %v\n", len(s), cap(s), s)
	}

	// slicing shares the backing array!
	a := []int{1, 2, 3, 4, 5}
	b := a[1:3]                              // [2 3], len 2, cap 4
	b[0] = 99                                // also changes a[1]
	fmt.Println(a, b)                        // [1 99 3 4 5] [99 3]
	b = append(b, 100)                       // writes into a[3]: surprise!
	fmt.Println(a)                           // [1 99 3 100 5]
	c := a[1:3:3]                            // full slice expression: cap limited to 2 → append must copy
	c = append(c, 7)
	fmt.Println(a, c)                        // a unchanged by this append

	// copy makes independent data
	d := make([]int, len(a))
	copy(d, a)

	// the slices package (Go 1.21+)
	nums := []int{5, 2, 8, 1}
	slices.Sort(nums)
	idx, found := slices.BinarySearch(nums, 5)
	fmt.Println(nums, idx, found, slices.Contains(nums, 8), slices.Index(nums, 8), slices.Max(nums))
	nums = slices.DeleteFunc(nums, func(n int) bool { return n%2 == 0 })
	slices.Reverse(nums)
	fmt.Println(nums, slices.Equal(d, a))

	// remove the element at index i (order kept)
	xs := []string{"a", "b", "c", "d"}
	xs = slices.Delete(xs, 1, 2)
	fmt.Println(xs) // [a c d]

	// nil vs empty: both have len 0. JSON encodes nil as null and empty as [].
	var nilS []int
	empty := []int{}
	fmt.Println(nilS == nil, empty == nil, len(nilS), len(empty))
}
🚫 The slice aliasing bug

Functions that receive a slice can modify the caller's elements, and an append may or may not affect the caller depending on the capacity. Rule: if a function appends, return the new slice (s = add(s, x)). If you store a sub-slice of a big buffer long-term, copy it (slices.Clone) so the big buffer can be garbage-collected.

Maps

package main

import (
	"fmt"
	"maps"
	"slices"
)

func main() {
	stock := map[string]int{"apple": 5, "pear": 0}
	stock["kiwi"] = 7            // insert/update
	qty := stock["banana"]       // missing key → zero value (0)
	qty, ok := stock["pear"]     // comma-ok: distinguishes "0 in stock" from "unknown"
	fmt.Println(qty, ok)
	delete(stock, "apple")       // no-op if absent
	fmt.Println(len(stock))

	// iteration order is RANDOM on purpose: sort the keys when the order matters
	keys := slices.Sorted(maps.Keys(stock)) // Go 1.23 iterators
	for _, k := range keys {
		fmt.Println(k, stock[k])
	}

	// map of slices, set idiom, struct values
	byCity := map[string][]string{}
	byCity["Pune"] = append(byCity["Pune"], "order-1") // append on a nil slice works
	seen := map[string]struct{}{}                     // a set: empty struct uses 0 bytes
	seen["x"] = struct{}{}
	_, exists := seen["x"]
	fmt.Println(byCity, exists)

	type Point struct{ X, Y int }
	grid := map[Point]string{{1, 2}: "shop"} // comparable structs can be keys
	fmt.Println(grid[Point{1, 2}])

	clone := maps.Clone(stock)
	maps.DeleteFunc(clone, func(k string, v int) bool { return v == 0 })
	fmt.Println(clone)
}
⚠️ Map rules
  • Writing to a nil map panics: always make it or use a literal.
  • Maps are not safe for concurrent writes. The runtime crashes with "concurrent map writes". Use a mutex or sync.Map (Level 3).
  • You can't take the address of a map element (&m[k]). Store pointers, or reassign the whole value.

Strings, bytes and runes

package main

import (
	"fmt"
	"strings"
	"unicode/utf8"
)

func main() {
	s := "Hi, 世界"
	fmt.Println(len(s))                    // 10 BYTES (each Chinese char is 3 bytes in UTF-8)
	fmt.Println(utf8.RuneCountInString(s)) // 6 characters (runes)
	fmt.Println(s[0], string(s[0]))        // 72 "H": indexing gives a BYTE
	runes := []rune(s)
	fmt.Println(string(runes[4]))          // 世

	// strings are immutable: build them efficiently with strings.Builder
	var sb strings.Builder
	for i := range 3 {
		fmt.Fprintf(&sb, "item-%d;", i)
	}
	fmt.Println(sb.String())

	// the strings package
	fmt.Println(strings.Split("a,b,c", ","), strings.Fields("  a  b "),
		strings.Contains(s, "世"), strings.HasPrefix(s, "Hi"),
		strings.ReplaceAll("a-b-c", "-", "+"), strings.TrimSpace("  x  "),
		strings.EqualFold("Go", "GO"), strings.Repeat("ab", 3))
	before, after, found := strings.Cut("user=alice", "=")
	fmt.Println(before, after, found)

	// raw string literals: no escapes, can span lines (JSON, SQL, regex)
	query := `SELECT id, name
FROM users WHERE email = $1`
	fmt.Println(query)
}

Embedding is composition, not inheritance

An embedded type's fields and methods are promoted, but there's no polymorphism: User is not an Address. If both define a method with the same name, the outer one wins (shadowing). Level 1 quiz
1. What does len("héllo") return and why?
6: len counts bytes, and "é" is 2 bytes in UTF-8. Use utf8.RuneCountInString for characters.
2. Why can append inside a function surprise the caller?
If there's spare capacity, append writes into the shared backing array (the caller's data beyond its len changes, and other sub-slices see it). If not, it allocates a new array and the caller doesn't see the appended element at all. Return the slice from the function.
3. What happens when you write to a nil map?
A runtime panic: "assignment to entry in nil map". Reading is fine (it returns the zero value).
4. What's the difference between new and make?
new(T) allocates a zero T and returns a *T, for any type. make initializes slices, maps and channels (internal structures) and returns the value itself, not a pointer.

Methods & interfaces: Go's way of doing abstraction

In one line: a type satisfies an interface automatically by having its methods. There's no implements keyword, so consumers can define tiny interfaces for exactly what they need.

Methods: value vs pointer receivers

package main

import "fmt"

type Cart struct {
	Items []string
	Total int
}

// value receiver: works on a COPY (read-only use)
func (c Cart) Count() int { return len(c.Items) }

// pointer receiver: can modify the original, and avoids copying large structs
func (c *Cart) Add(item string, price int) {
	c.Items = append(c.Items, item)
	c.Total += price
}

func main() {
	var c Cart       // zero value is usable
	c.Add("mug", 900) // Go takes &c automatically for addressable values
	c.Add("tee", 1500)
	fmt.Println(c.Count(), c.Total) // 2 2400
}

⚠️ Method sets

The method set of T contains only the value-receiver methods. *T has both. So if Add has a pointer receiver, a Cart value does not satisfy an interface requiring Add, but a *Cart does. That's the source of the "does not implement (method has pointer receiver)" compile error.

			fmt.Println("notify failed:", err)
		}
	}
}

func describe(v any) string {
	switch x := v.(type) {
	case nil:
		return "nil"
	case int:
		return fmt.Sprintf("int %d", x)
	case string:
		return fmt.Sprintf("string %q", x)
	case fmt.Stringer:
		return "stringer " + x.String()
	case error:
		return "error " + x.Error()
	default:
		return fmt.Sprintf("other %T", x)
	}
}

The nil interface trap (a classic interview question)

package main

import "fmt"

type MyErr struct{}

func (*MyErr) Error() string { return "my error" }

func mayFail(fail bool) error {
	var e *MyErr // typed nil pointer
	if fail {
		e = &MyErr{}
	}
	return e // ❌ returns an interface holding (type=*MyErr, value=nil), which is NOT nil
}

func main() {
	err := mayFail(false)
	fmt.Println(err == nil) // false!
	// ✅ fix: return a literal nil when there's no error:  if !fail { return nil }
}

An interface value is a pair (type, value). It's nil only when both are nil.

Interface design guidelines

  • Accept interfaces, return concrete structs. Callers get the full type, and your functions stay flexible.
  • Keep interfaces small (1–3 methods): io.Reader, fmt.Stringer, http.Handler.
  • Define interfaces where they're used (the consumer side), not next to the implementation. Don't create an interface "just in case".
  • Compose them: type ReadWriter interface { Reader; Writer }.

Error handling done right

In one line: errors are ordinary values that you return, check, wrap with context, and inspect with errors.Is/errors.As. There are no exceptions.

package main

import (
	"errors"
	"fmt"
	"io/fs"
	"os"
)

// 1) sentinel errors: fixed values callers compare against
var (
	ErrNotFound     = errors.New("not found")
	ErrInsufficient = errors.New("insufficient stock")
)

// 2) custom error types: carry structured data
type ValidationError struct {
	Field  string
	Reason string
}

func (e *ValidationError) Error() string { return e.Field + ": " + e.Reason }

func reserve(sku string, qty int) error {
	if qty <= 0 {
		return &ValidationError{Field: "qty", Reason: "must be positive"}
	}
	if sku == "GHOST" {
		return fmt.Errorf("reserve %s: %w", sku, ErrNotFound) // %w WRAPS: keeps the chain
	}
	return fmt.Errorf("reserve %s x%d: %w", sku, qty, ErrInsufficient)
}

func main() {
	err := reserve("GHOST", 1)
	fmt.Println(err)                         // reserve GHOST: not found
	fmt.Println(errors.Is(err, ErrNotFound)) // true: Is walks the wrap chain

	err = reserve("MUG", 0)
	var ve *ValidationError
	if errors.As(err, &ve) { // As finds the first error of that TYPE in the chain
		fmt.Println("bad field:", ve.Field)
	}

	// standard library errors work the same way
	_, err = os.Open("nope.txt")
	fmt.Println(errors.Is(err, fs.ErrNotExist)) // true
	var pe *fs.PathError
	fmt.Println(errors.As(err, &pe), pe.Op, pe.Path)

	// 3) several errors at once (validation, cleanup): errors.Join
	joined := errors.Join(errors.New("email required"), errors.New("name too long"))
	fmt.Println(joined)
}

The rules senior engineers follow

  1. Handle every error once: either handle it (log, fallback, return a response) or return it with context, never both (otherwise you get duplicate logs).
  2. Add context when you return: fmt.Errorf("load order %s: %w", id, err). That gives you a readable trail: handler: place order: reserve stock: connection refused.
  3. %w vs %v: %w makes the cause part of your API (callers can Is/As it). Use %v to hide implementation details (don't leak sql.ErrNoRows through layers; translate it into your domain's ErrNotFound).
  4. Error strings are lowercase with no punctuation at the end, because they get chained.
  5. Map errors at the edge: the HTTP handler turns domain errors into status codes (NotFound → 404, Validation → 400, unknown → 500 + a log).
  6. Don't panic in libraries or handlers. A recover middleware catches programmer bugs.
func statusFor(err error) int {
	var ve *ValidationError
	switch {
	case errors.As(err, &ve):
		return http.StatusBadRequest
	case errors.Is(err, ErrNotFound):
		return http.StatusNotFound
	case errors.Is(err, ErrInsufficient):
		return http.StatusConflict
	case errors.Is(err, context.DeadlineExceeded):
		return http.StatusGatewayTimeout
	default:
		return http.StatusInternalServerError
	}
}

package main

import (
	"cmp"
	"errors"
	"fmt"
)

// a constraint is an interface describing the allowed types
type Number interface {
	~int | ~int64 | ~float64 // ~ = any type whose UNDERLYING type is int etc. (e.g. type Cents int)
}

func Sum[T Number](xs []T) T {
	var total T
	for _, x := range xs {
		total += x
	}
	return total
}

func MaxBy[T any, K cmp.Ordered](xs []T, key func(T) K) (T, error) {
	var zero T
	if len(xs) == 0 {
		return zero, errors.New("empty")
	}
	best := xs[0]
	for _, x := range xs[1:] {
		if key(x) > key(best) {
			best = x
		}
	}
	return best, nil
}

// a generic type: a typed, reusable container
type Stack[T any] struct{ items []T }

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }
func (s *Stack[T]) Pop() (T, bool) {
	var zero T
	if len(s.items) == 0 {
		return zero, false
	}
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, true
}

// a generic result type for APIs
type Page[T any] struct {
	Items      []T    `json:"items"`
	NextCursor string `json:"next_cursor,omitempty"`
}

type Cents int

type Product struct {
	Name  string
	Price Cents
}

func main() {
	fmt.Println(Sum([]int{1, 2, 3}), Sum([]float64{1.5, 2.5}), Sum([]Cents{100, 250}))
	p, _ := MaxBy([]Product{{"mug", 900}, {"tee", 1500}}, func(p Product) Cents { return p.Price })
	fmt.Println(p.Name)

	var s Stack[string]
	s.Push("a")
	s.Push("b")
	v, _ := s.Pop()
	fmt.Println(v)
	fmt.Printf("%+v\n", Page[Product]{Items: []Product{{"mug", 900}}})
}

Iterators: range over functions (Go 1.23+)

A function of the form func(yield func(V) bool) can be used in a for range loop. That's a standard way to expose lazy sequences (DB rows, paginated APIs, tree walks) without building a whole slice.

package main

import (
	"fmt"
	"iter"
	"maps"
	"slices"
)

// Fibonacci as a lazy, infinite sequence
func Fib() iter.Seq[int] {
	return func(yield func(int) bool) {
		a, b := 0, 1
		for {
			if !yield(a) { // the consumer did 'break' → stop producing
				return
			}
			a, b = b, a+b
		}
	}
}

// paginated API, exposed as a simple iterator over all items
func AllOrders(fetch func(cursor string) ([]string, string)) iter.Seq2[int, string] {
	return func(yield func(int, string) bool) {
		i, cursor := 0, ""
		for {
			page, next := fetch(cursor)
			for _, o := range page {
				if !yield(i, o) {
					return
				}
				i++
			}
			if next == "" {
				return
			}
			cursor = next
		}
	}
}

func main() {
	for n := range Fib() {
		if n > 50 {
			break
		}
		fmt.Print(n, " ")
	}
	fmt.Println()

	pages := map[string][]string{"": {"o-1", "o-2"}, "p2": {"o-3"}}
	nexts := map[string]string{"": "p2", "p2": ""}
	for i, o := range AllOrders(func(c string) ([]string, string) { return pages[c], nexts[c] }) {
		fmt.Println(i, o)
	}

	m := map[string]int{"b": 2, "a": 1}
	fmt.Println(slices.Sorted(maps.Keys(m)))                 // [a b]
	fmt.Println(slices.Collect(maps.Values(map[int]int{1: 9}))) // [9]
}

2. errors.Is vs errors.As?

It returned a typed nil pointer (e.g. *MyErr(nil)) as an error. The interface has a type, so it isn't nil. Return a literal nil.

Goroutines, channels & select

In one line: a goroutine is a function running concurrently, costing only a few KB. Channels are typed pipes that pass values between goroutines and synchronize them.

Goroutines are kitchen staff and channels are the order window between them. The cook puts a plate on the window (send), and the waiter picks it up (receive). With no buffer, the cook waits until a waiter takes the plate. With a buffer of 3, up to 3 plates can wait on the counter.

package main

import "fmt"

func producer(n int) <-chan int { // returns a RECEIVE-ONLY channel
	out := make(chan int)
	go func() {
		defer close(out) // the SENDER closes; it means "no more values"
		for i := range n {
			out <- i // blocks until someone receives (unbuffered)
		}
	}()
	return out
}

func square(in <-chan int) <-chan int {
	out := make(chan int)
	go func() {
		defer close(out)
		for v := range in { // the range loop ends when 'in' is closed and drained
			out <- v * v
		}
	}()
	return out
}

func main() {
	for v := range square(producer(5)) { // a pipeline: producer → square → main
		fmt.Print(v, " ")
	}
	fmt.Println()

	buf := make(chan string, 2) // buffered: sends don't block until it's full
	buf <- "a"
	buf <- "b"
	fmt.Println(len(buf), cap(buf))
	close(buf)
	v, ok := <-buf  // "a" true
	fmt.Println(v, ok)
	<-buf
	v, ok = <-buf   // "" false: closed and empty → zero value, ok=false
	fmt.Printf("%q %v\n", v, ok)
}

package main

	fast := make(chan string)
	slow := make(chan string)

	for range 2 {
		select { // waits for whichever case is ready first (random if several are)
		case m := <-fast:
			fmt.Println("got", m)
		case m := <-slow:
			fmt.Println("got", m)
		case <-timeout:
			fmt.Println("timed out waiting")
		}
	}

	ch := make(chan int, 1)
	select {
	case ch <- 1:
		fmt.Println("sent")
	default:
		fmt.Println("channel full, dropping")
	}

	tick := time.NewTicker(20 * time.Millisecond)
	defer tick.Stop()
	for i := range 3 {
		<-tick.C
		fmt.Println("tick", i)
	}

Channels or mutexes?

Use channels to pass ownership of data or coordinate stages (pipelines, worker pools, signals). Use a mutex to protect shared state (a cache, counters, a map). Mutex code is often simpler; don't force channels everywhere.

sync, atomic & the memory model

package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

// a concurrency-safe cache: an RWMutex allows many readers OR one writer
type Cache struct {
	mu   sync.RWMutex
	data map[string]string
}

func NewCache() *Cache { return &Cache{data: map[string]string{}} }

func (c *Cache) Get(k string) (string, bool) {
	c.mu.RLock()
	defer c.mu.RUnlock()
	v, ok := c.data[k]
	return v, ok
}

func (c *Cache) Set(k, v string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.data[k] = v
}

var (
	loadOnce sync.Once
	config   map[string]string
)

func Config() map[string]string { // lazy, thread-safe initialization
	loadOnce.Do(func() { config = map[string]string{"env": "prod"} })
	return config
}

func main() {
	c := NewCache()
	var hits atomic.Int64 // lock-free counter
	var wg sync.WaitGroup
	for i := range 100 {
		wg.Add(1)
		go func() {
			defer wg.Done()
			c.Set(fmt.Sprint(i%10), "v")
			if _, ok := c.Get("1"); ok {
				hits.Add(1)
			}
		}()
	}
	wg.Wait()
	fmt.Println(len(c.data), hits.Load() > 0, Config()["env"])

	// sync.Pool: reuse temporary objects to cut GC pressure (buffers in hot paths)
	pool := sync.Pool{New: func() any { return make([]byte, 0, 4096) }}
	b := pool.Get().([]byte)
	b = append(b[:0], "hello"...)
	pool.Put(b[:0])
	fmt.Println("pooled buffer reused")
}

⚠️ Mutex rules
  • Never copy a struct containing a mutex (use pointer receivers; go vet catches copies).
  • Keep critical sections small. Never do I/O (DB, HTTP) while holding a lock.
  • Lock in a consistent order across code paths, or you'll deadlock.

The memory model in one paragraph

Without synchronization, there's no guarantee that one goroutine ever sees another's writes, or sees them in order. Synchronization creates "happens-before" edges: a channel send happens before the matching receive completes, an Unlock happens before the next Lock, wg.Done happens before wg.Wait returns, and atomics are synchronized. If two goroutines access the same variable and at least one writes, without such an edge, it's a data race: undefined behaviour. Always run tests with -race.

In one line: a context.Context flows through every call in a request. When the client disconnects or the deadline passes, everything downstream (DB queries, HTTP calls, goroutines) stops.

package main

import (
	"context"
	"errors"
	"fmt"
	"time"
)

// every function doing I/O takes ctx as its FIRST parameter
func queryDB(ctx context.Context, q string) (string, error) {
	select {
	case <-time.After(300 * time.Millisecond): // simulated slow query
		return "rows for " + q, nil
	case <-ctx.Done(): // cancelled or deadline exceeded
		return "", fmt.Errorf("queryDB: %w", ctx.Err())
	}
}

type ctxKey string

const requestIDKey ctxKey = "request_id" // an unexported key type avoids collisions

func handler(ctx context.Context) {
	ctx, cancel := context.WithTimeout(ctx, 100*time.Millisecond)
	defer cancel() // ALWAYS call cancel to release resources
	_, err := queryDB(ctx, "SELECT …")
	if errors.Is(err, context.DeadlineExceeded) {
		fmt.Println("request", ctx.Value(requestIDKey), "timed out:", err)
	}
}

func main() {
	ctx := context.WithValue(context.Background(), requestIDKey, "req-42")
	handler(ctx)

	// manual cancellation fans out to every goroutine sharing the context
	ctx2, cancel := context.WithCancelCause(context.Background())
	done := make(chan struct{})
	go func() {
		<-ctx2.Done()
		fmt.Println("worker stopping:", context.Cause(ctx2))
		close(done)
	}()
	cancel(errors.New("shutdown requested"))
	<-done
}

	results := make(chan Result)

		wg.Add(1)

Level 3 quiz
1. Who should close a channel?
The sender (the owner) once it's done sending. Receivers never close. With several senders, coordinate with a WaitGroup and close once.
2. What happens when you receive from a closed channel?
It returns any remaining buffered values, then the zero value with ok=false, immediately and forever.
3. Why give the result channel a buffer of 1 in a timeout pattern?
So the worker goroutine can always complete its send and exit even if nobody receives (no leak).
4. When should you use context.WithValue?
Only for request-scoped data that crosses API boundaries (request ID, auth, tracing), never for dependencies or optional parameters.

Escape analysis: stack vs heap

go build -gcflags='-m' ./...     # prints decisions like "moved to heap: u" or "does not escape"

Values that escape (returned pointers, stored in interfaces, captured by long-lived closures, too big for the stack) are heap-allocated and cost GC work. In hot paths: avoid unnecessary pointers, pre-size slices and maps, reuse buffers (sync.Pool), avoid fmt.Sprintf in tight loops, and avoid converting between []byte and string repeatedly.

  2. Fix the algorithm and the I/O first: N+1 queries, missing indexes, chatty services, no caching. These are 100× wins.

Runtime internals: the scheduler, goroutine stacks & the GC

The G-M-P scheduler

  • An M must hold a P to run Go code. A P has a local queue of runnable Gs. Idle Ps steal work from others.
  • When a G blocks in a syscall, its M detaches from the P and another M takes the P, so other goroutines keep running.
  • Network I/O doesn't block threads: the netpoller (epoll/kqueue) parks the goroutine and wakes it when the socket is ready. That's why 100k connections are cheap.
  • Goroutines are preempted asynchronously (since 1.14), so a tight loop can't starve the others.
  • Goroutine stacks start at ~2–8 KB and grow and shrink by copying.

The garbage collector

  • Concurrent, tri-color mark-and-sweep (non-generational, non-moving), with write barriers during marking. Stop-the-world pauses are typically well under a millisecond.
  • The GC cost is proportional to the live heap and the allocation rate, so reducing allocations reduces GC CPU.
  • Go 1.25 shipped an experimental new GC ("Green Tea", GOEXPERIMENT=greenteagc) with better memory locality for many workloads.
  • Maps use Swiss tables since Go 1.24 (faster lookups, less memory).
Level 4 quiz
1. Why is GOMEMLIMIT important in Kubernetes?
Without it, the GC only follows GOGC, and the heap can grow past the container memory limit and get OOM-killed. A limit at ~90% of the container's makes the GC work harder near the limit.
2. Your p99 latency spikes but CPU is low. Which profile?
An execution trace (go tool trace) and the block/mutex profiles show waiting: lock contention, GC assists, scheduler delays. Also check the downstream latency.
3. How do 100k idle WebSocket connections not need 100k threads?
Each connection is a goroutine parked in the netpoller. Only a few OS threads (one per P) run the goroutines that are actually ready.

type Product struct {

	Name       string `json:"name"`

var ErrNotFound = errors.New("not found")

type Store struct {
	mu    sync.RWMutex
	items map[string]Product
	seq   int
}

func NewStore() *Store { return &Store{items: map[string]Product{}} }

func (s *Store) Create(p Product) Product {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.seq++
	p.ID = "p-" + strconv.Itoa(s.seq)
	s.items[p.ID] = p
	return p
}

func (s *Store) Get(id string) (Product, error) {
	s.mu.RLock()
	defer s.mu.RUnlock()
	p, ok := s.items[id]
	if !ok {
		return Product{}, ErrNotFound
	}
	return p, nil
}

func (s *Store) List() []Product {
	s.mu.RLock()
	defer s.mu.RUnlock()
	out := make([]Product, 0, len(s.items))
	for _, p := range s.items {
		out = append(out, p)
	}
	return out
}

// ---------- JSON helpers ----------
func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	_ = json.NewEncoder(w).Encode(v)
}

// RFC 9457 "problem details" style errors
func writeError(w http.ResponseWriter, status int, msg string) {
	writeJSON(w, status, map[string]any{"title": http.StatusText(status), "status": status, "detail": msg})
}

func decodeJSON(w http.ResponseWriter, r *http.Request, dst any) error {
	r.Body = http.MaxBytesReader(w, r.Body, 1<<20) // 1 MB limit: protects against huge bodies
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(dst); err != nil {
		return fmt.Errorf("invalid JSON: %w", err)
	}
	return nil
}

type API struct {
	store *Store
	log   *slog.Logger

func (a *API) routes() http.Handler {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, r *http.Request) { w.Write([]byte("ok")) })
	mux.HandleFunc("GET /v1/products", a.listProducts)
	mux.HandleFunc("POST /v1/products", a.createProduct)
	mux.HandleFunc("GET /v1/products/{id}", a.getProduct) // path parameter (Go 1.22+)
	// middleware chain: outermost first
	return a.recoverer(a.requestID(a.logRequests(mux)))
}

func (a *API) listProducts(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, http.StatusOK, map[string]any{"items": a.store.List()})
}

func (a *API) getProduct(w http.ResponseWriter, r *http.Request) {
	p, err := a.store.Get(r.PathValue("id"))
	if errors.Is(err, ErrNotFound) {
		writeError(w, http.StatusNotFound, "product not found")
		return
	}
	writeJSON(w, http.StatusOK, p)
}

func (a *API) createProduct(w http.ResponseWriter, r *http.Request) {
	var in struct {
		Name       string `json:"name"`
		PriceCents int    `json:"price_cents"`
	}
	if err := decodeJSON(w, r, &in); err != nil {
		writeError(w, http.StatusBadRequest, err.Error())
		return
	}
	if in.Name == "" || in.PriceCents <= 0 { // validation
		writeError(w, http.StatusUnprocessableEntity, "name required and price_cents must be > 0")
		return
	}
	p := a.store.Create(Product{Name: in.Name, PriceCents: in.PriceCents})
	w.Header().Set("Location", "/v1/products/"+p.ID)
	writeJSON(w, http.StatusCreated, p)
}

// ---------- middleware ----------
type ctxKey string

const reqIDKey ctxKey = "req_id"

func (a *API) requestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			b := make([]byte, 8)
			rand.Read(b)
			id = hex.EncodeToString(b)
		}
		w.Header().Set("X-Request-ID", id)
		next.ServeHTTP(w, r.WithContext(context.WithValue(r.Context(), reqIDKey, id)))
	})
}

type statusRecorder struct {
	http.ResponseWriter
	status int
}

func (s *statusRecorder) WriteHeader(code int) { s.status = code; s.ResponseWriter.WriteHeader(code) }

func (a *API) logRequests(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		rec := &statusRecorder{ResponseWriter: w, status: http.StatusOK}
		next.ServeHTTP(rec, r)
		a.log.Info("http", "method", r.Method, "path", r.URL.Path, "status", rec.status,
			"dur_ms", time.Since(start).Milliseconds(), "req_id", r.Context().Value(reqIDKey))
	})
}

func (a *API) recoverer(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if v := recover(); v != nil {
				a.log.Error("panic", "value", v, "path", r.URL.Path)
				writeError(w, http.StatusInternalServerError, "internal error")
			}
		}()
		next.ServeHTTP(w, r)
	})
}

func main() {
	log := slog.New(slog.NewJSONHandler(os.Stdout, nil))
	api := &API{store: NewStore(), log: log}

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           api.routes(),
		ReadHeaderTimeout: 5 * time.Second, // protects against slowloris attacks
		ReadTimeout:       15 * time.Second,
		WriteTimeout:      15 * time.Second,
		IdleTimeout:       60 * time.Second,
	}

	ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
	defer stop()

	go func() {
		log.Info("listening", "addr", srv.Addr)
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			log.Error("server error", "err", err)
			os.Exit(1)
		}
	}()

	<-ctx.Done() // SIGTERM from Kubernetes / Ctrl+C
	log.Info("shutting down")
	shutdownCtx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
	defer cancel()
	if err := srv.Shutdown(shutdownCtx); err != nil { // stop accepting, finish in-flight requests
		log.Error("forced shutdown", "err", err)
	}
}

🏢 Zero-downtime migrations

Use expand → migrate → contract: add the nullable column, deploy code that writes both the old and new columns, backfill, switch the reads, then drop the old one in a later release. Create indexes CONCURRENTLY. Run migrations as a separate job (a Kubernetes Job or init step), not on app startup across N replicas.

Database performance must-knows

  • N+1 queries: fetching orders and then items per order in a loop. Use JOINs, WHERE id = ANY($1) batch queries, or dataloaders (GraphQL).
  • Indexes for every WHERE/ORDER BY on hot paths. Check them with EXPLAIN ANALYZE.
  • Keyset pagination instead of OFFSET for large tables.
  • Pool sizing: replicas × MaxConns ≤ the database's connection budget. Use PgBouncer for many replicas.
  • Context timeouts on every query, so a slow DB can't pile up goroutines.

Level 5 quiz
1. Why is http.Get(url) dangerous in a service?
It uses http.DefaultClient, which has no timeout, so a hung downstream service blocks goroutines forever. Use a configured client and request contexts.
2. How do you reserve stock without a race condition?
A conditional atomic update: UPDATE … SET available = available - $2 WHERE sku=$1 AND available >= $2, then check RowsAffected. Or SELECT … FOR UPDATE inside a transaction.
3. Where should refresh tokens be stored in a browser app?
An HttpOnly, Secure, SameSite cookie (not readable by JavaScript), hashed server-side, and rotated on each use.
4. What's the difference between 401 and 403?
401 Unauthorized = not authenticated (missing or invalid credentials). 403 Forbidden = authenticated, but not allowed.

Conventions that make an API pleasant

  • Plural nouns and lowercase-kebab paths. JSON fields in snake_case (or camelCase): pick one and keep it.
  • Pagination: cursor-based ?limit=50&cursor=eyJ… → {"items":[…],"next_cursor":"…"}. Cap the limit.
  • Filtering and sorting: ?status=PAID&created_after=2026-10-01&sort=-created_at (allow-listed fields).
  • Errors: one consistent shape, e.g. RFC 9457 problem details {"type","title","status","detail","errors":{…}}.
  • Versioning: /v1/ in the path (simple and visible). Only additive changes inside a version.
  • Money in minor units + a currency. Time in RFC 3339 UTC. IDs as opaque strings.
  • Caching and concurrency: ETag + If-None-Match (304) for reads, If-Match for safe updates.
  • Document it with OpenAPI 3.1, and generate server stubs and clients (oapi-codegen, ogen) or generate the spec from code.

Idempotency keys: safe retries for POST

// client sends: Idempotency-Key: 2f1c…  (a UUID per logical operation)
func Idempotent(rdb *redis.Client, next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		key := r.Header.Get("Idempotency-Key")
		if key == "" || r.Method != http.MethodPost {
			next.ServeHTTP(w, r)
			return
		}
		rk := "idem:" + userID(r) + ":" + key // scope per caller
		if cached, err := rdb.Get(r.Context(), rk).Bytes(); err == nil {
			var resp storedResponse
			json.Unmarshal(cached, &resp)
			if resp.Status == 0 { // first request still running
				writeError(w, http.StatusConflict, "request in progress")
				return
			}
			w.Header().Set("Idempotent-Replayed", "true")
			w.WriteHeader(resp.Status)
			w.Write(resp.Body) // replay the ORIGINAL response
			return
		}
		if ok, _ := rdb.SetNX(r.Context(), rk, `{"status":0}`, 24*time.Hour).Result(); !ok {
			writeError(w, http.StatusConflict, "request in progress")
			return
		}
		rec := httptest.NewRecorder() // capture the response
		next.ServeHTTP(rec, r)
		b, _ := json.Marshal(storedResponse{Status: rec.Code, Body: rec.Body.Bytes()})
		rdb.Set(r.Context(), rk, b, 24*time.Hour)
		for k, v := range rec.Header() {
			w.Header()[k] = v
		}
		w.WriteHeader(rec.Code)
		w.Write(rec.Body.Bytes())
	})
}

// Header format (Stripe-style): "t=1761200000,v1=<hex hmac>"
// signed payload = timestamp + "." + raw body  → protects against replay with old timestamps
func Sign(secret []byte, body []byte, ts time.Time) string {
	mac := hmac.New(sha256.New, secret)
	fmt.Fprintf(mac, "%d.", ts.Unix())
	mac.Write(body)
	return fmt.Sprintf("t=%d,v1=%s", ts.Unix(), hex.EncodeToString(mac.Sum(nil)))
}

var ErrBadSignature = errors.New("invalid webhook signature")

func Verify(secret []byte, body []byte, header string, now time.Time, tolerance time.Duration) error {
	var ts int64
	var sigs []string
	for _, part := range strings.Split(header, ",") {
		k, v, _ := strings.Cut(part, "=")
		switch k {
		case "t":
			ts, _ = strconv.ParseInt(v, 10, 64)
		case "v1":
			sigs = append(sigs, v) // several v1 values allowed during secret rotation
		}
	}
	if ts == 0 || len(sigs) == 0 {
		return ErrBadSignature
	}
	if d := now.Sub(time.Unix(ts, 0)); d > tolerance || d < -tolerance {
		return fmt.Errorf("%w: timestamp outside tolerance", ErrBadSignature)
	}
	mac := hmac.New(sha256.New, secret)
	fmt.Fprintf(mac, "%d.", ts)
	mac.Write(body)
	expected := mac.Sum(nil)
	for _, s := range sigs {
		got, err := hex.DecodeString(s)
		if err == nil && hmac.Equal(got, expected) { // constant-time comparison
			return nil
		}
	}
	return ErrBadSignature
}

func (h *Handler) PaymentWebhook(w http.ResponseWriter, r *http.Request) {
	body, err := io.ReadAll(http.MaxBytesReader(w, r.Body, 1<<20)) // need the RAW bytes for the signature
	if err != nil {
		http.Error(w, "too large", http.StatusRequestEntityTooLarge)
		return
	}
	if err := Verify(h.secret, body, r.Header.Get("Webhook-Signature"), time.Now(), 5*time.Minute); err != nil {
		http.Error(w, "bad signature", http.StatusUnauthorized)
		return
	}
	var evt struct {
		ID   string          `json:"id"`
		Type string          `json:"type"`
		Data json.RawMessage `json:"data"`
	}
	if err := json.Unmarshal(body, &evt); err != nil {
		http.Error(w, "bad json", http.StatusBadRequest)
		return
	}
	// idempotency: providers retry, so the same event can arrive several times
	inserted, err := h.store.InsertInboxEvent(r.Context(), evt.ID, evt.Type, body) // INSERT … ON CONFLICT DO NOTHING
	if err != nil {
		http.Error(w, "retry later", http.StatusServiceUnavailable) // non-2xx → the provider retries
		return
	}
	if inserted {
		h.queue.Enqueue(evt.ID) // process ASYNCHRONOUSLY: acknowledge fast (providers time out after a few seconds)
	}
	w.WriteHeader(http.StatusOK)
}

func (d *Dispatcher) deliver(ctx context.Context, del Delivery) {
	ctx, cancel := context.WithTimeout(ctx, 10*time.Second)
	defer cancel()
	req, _ := http.NewRequestWithContext(ctx, http.MethodPost, del.URL, bytes.NewReader(del.Payload))
	req.Header.Set("Content-Type", "application/json")
	req.Header.Set("Webhook-Id", del.EventID)                         // receivers dedupe on this
	req.Header.Set("Webhook-Signature", Sign(del.Secret, del.Payload, time.Now()))
	res, err := d.client.Do(req)                                     // the client blocks private IPs (SSRF!)
	if err == nil {
		io.Copy(io.Discard, io.LimitReader(res.Body, 64<<10))
		res.Body.Close()
	}
	if err == nil && res.StatusCode < 300 {
		d.store.MarkDelivered(ctx, del.ID)
		return
	}
	next := backoff(del.Attempt) // 1m, 5m, 30m, 2h, 6h, 12h, 24h … then give up
	if del.Attempt >= 10 {
		d.store.MarkFailed(ctx, del.ID) // notify the customer, disable the endpoint after repeated failures
		return
	}
	d.store.ScheduleRetry(ctx, del.ID, time.Now().Add(next))
}

WebSocket: a chat/notification hub

type Client struct {
	userID string
	send   chan []byte // buffered: a slow client mustn't block the hub
}

type Hub struct {
	mu      sync.RWMutex
	clients map[string]map[*Client]struct{} // userID → connections (several tabs/devices)
}

func (h *Hub) Add(c *Client) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.clients[c.userID] == nil {
		h.clients[c.userID] = map[*Client]struct{}{}
	}
	h.clients[c.userID][c] = struct{}{}
}

func (h *Hub) Remove(c *Client) {
	h.mu.Lock()
	defer h.mu.Unlock()
	delete(h.clients[c.userID], c)
}

func (h *Hub) SendToUser(userID string, msg []byte) {
	h.mu.RLock()
	defer h.mu.RUnlock()
	for c := range h.clients[userID] {
		select {
		case c.send <- msg:
		default: // buffer full → drop (or disconnect the slow client)
		}
	}
}

func (h *Hub) ServeWS(w http.ResponseWriter, r *http.Request) {
	user := auth.UserFrom(r.Context()) // authenticate BEFORE upgrading (cookie or a short-lived token in the query)
	conn, err := websocket.Accept(w, r, &websocket.AcceptOptions{OriginPatterns: []string{"shop.dev"}})
	if err != nil {
		return
	}
	defer conn.CloseNow()
	conn.SetReadLimit(64 << 10)

	c := &Client{userID: user.ID, send: make(chan []byte, 32)}
	h.Add(c)
	defer h.Remove(c)

	ctx, cancel := context.WithCancel(r.Context())
	defer cancel()

	go func() { // reader: handles incoming messages; any error cancels everything
		defer cancel()
		for {
			_, data, err := conn.Read(ctx)
			if err != nil {
				return
			}
			h.handleIncoming(ctx, c, data) // e.g. "typing", "ack", chat message
		}
	}()

	ping := time.NewTicker(25 * time.Second) // keepalive: detects dead connections, keeps proxies open
	defer ping.Stop()
	for { // writer: the ONLY goroutine that writes to the connection
		select {
		case <-ctx.Done():
			conn.Close(websocket.StatusNormalClosure, "")
			return
		case msg := <-c.send:
			wctx, wcancel := context.WithTimeout(ctx, 5*time.Second)
			err := conn.Write(wctx, websocket.MessageText, msg)
			wcancel()
			if err != nil {
				return
			}
		case <-ping.C:
			pctx, pcancel := context.WithTimeout(ctx, 5*time.Second)
			err := conn.Ping(pctx)
			pcancel()
			if err != nil {
				return
			}
		}
	}
}

		return nil, status.Error(codes.Internal, "internal error") // don't leak internals

func (s *OrderServer) WatchOrder(req *ordersv1.WatchOrderRequest, stream grpc.ServerStreamingServer[ordersv1.OrderEvent]) error {

		}
	}

}

Finding boundaries with DDD (Domain-Driven Design)

  • Bounded context: the area where one model and language apply. "Product" means something different to Catalog (descriptions, images), Inventory (stock per warehouse) and Pricing (price lists). Separate contexts become separate services.
  • Aggregate: a cluster of objects changed together in one transaction, with one root (an Order with its OrderItems). Reference other aggregates by ID.
  • Domain events: the facts other contexts react to (OrderPlaced).
  • Context map: how the contexts relate: an upstream/downstream relationship, and an anti-corruption layer that translates foreign models.

The rules of data ownership

  1. Database per service. No service reads another's tables. Share data through APIs or events.
  2. Need someone else's data often? Keep a local read-only copy, updated from their events (CQRS).
  3. A cross-service business transaction is a saga (Level 9), not a distributed transaction.

Retry with exponential backoff + jitter (runnable)

package main

import (
	"context"
	"errors"
	"fmt"
	"math/rand/v2"
	"time"
)

var ErrTransient = errors.New("transient")

// Retry calls fn until it succeeds, returns a non-retryable error, or ctx ends.
func Retry(ctx context.Context, attempts int, base time.Duration, fn func(context.Context) error) error {
	var err error
	for i := range attempts {
		if err = fn(ctx); err == nil || !errors.Is(err, ErrTransient) {
			return err // success, or a permanent error: don't retry
		}
		backoff := base << i                                    // 100ms, 200ms, 400ms…
		sleep := time.Duration(rand.Int64N(int64(backoff) + 1)) // "full jitter" avoids retry storms
		select {
		case <-time.After(sleep):
		case <-ctx.Done():
			return ctx.Err()
		}
	}
	return fmt.Errorf("after %d attempts: %w", attempts, err)
}

func main() {
	calls := 0
	err := Retry(context.Background(), 5, 50*time.Millisecond, func(ctx context.Context) error {
		calls++
		if calls < 3 {
			return fmt.Errorf("upstream 503: %w", ErrTransient)
		}
		return nil
	})
	fmt.Println("calls:", calls, "err:", err) // calls: 3 err: <nil>
}
⚠️ Retry safely
  • Retry only idempotent operations, or send an idempotency key.
  • Retry only transient errors (503, UNAVAILABLE, timeouts), never 400 or 404.
  • Retry at one layer only. Retries at 3 layers × 3 attempts = 27× load during an outage.
  • Use a retry budget (at most ~10% extra traffic) and respect Retry-After.

func RunConsumer(ctx context.Context, cl *kgo.Client, db *pgxpool.Pool) error {
	for {
		fetches := cl.PollFetches(ctx)
		if fetches.IsClientClosed() || ctx.Err() != nil {
			return ctx.Err()
		}
		var procErr error
		fetches.EachRecord(func(r *kgo.Record) {
			if procErr != nil {
				return
			}
			procErr = handle(ctx, db, r)
		})
		if procErr != nil {
			slog.Error("processing failed, will retry batch", "err", procErr)
			time.Sleep(time.Second) // records are re-polled because we did NOT commit
			continue
		}
		if err := cl.CommitUncommittedOffsets(ctx); err != nil {
			slog.Error("commit failed", "err", err)
		}
	}
}

func handle(ctx context.Context, db *pgxpool.Pool, r *kgo.Record) error {
	var evt Event
	if err := json.Unmarshal(r.Value, &evt); err != nil {
		return publishDLQ(ctx, r, err) // poison pill → DLQ, don't block the partition

		tag, err := tx.Exec(ctx, `INSERT INTO processed_events (event_id) VALUES ($1) ON CONFLICT DO NOTHING`, evt.ID)

			return err // duplicate → nothing to do
		}
		return applyBusinessLogic(ctx, tx, evt)
	})
}

func RelayOutbox(ctx context.Context, db *pgxpool.Pool, cl *kgo.Client) {
	t := time.NewTicker(200 * time.Millisecond)
	defer t.Stop()
	for {
		select {
		case <-ctx.Done():
			return
		case <-t.C:
		}
		err := WithTx(ctx, db, func(tx pgx.Tx) error {
			rows, err := tx.Query(ctx, `
				SELECT id, topic, key, payload FROM outbox
				ORDER BY created_at LIMIT 100
				FOR UPDATE SKIP LOCKED`)
			if err != nil {
				return err
			}
			msgs, err := pgx.CollectRows(rows, pgx.RowToStructByPos[OutboxRow])
			if err != nil || len(msgs) == 0 {
				return err
			}
			recs := make([]*kgo.Record, len(msgs))
			ids := make([]string, len(msgs))
			for i, m := range msgs {
				recs[i] = &kgo.Record{Topic: m.Topic, Key: []byte(m.Key), Value: m.Payload,
					Headers: []kgo.RecordHeader{{Key: "eventId", Value: []byte(m.ID)}}}
				ids[i] = m.ID
			}
			if err := cl.ProduceSync(ctx, recs...).FirstErr(); err != nil {
				return err // the rollback keeps the rows → retried (at-least-once)
			}
			_, err = tx.Exec(ctx, `DELETE FROM outbox WHERE id = ANY($1)`, ids)
			return err
		})
		if err != nil {
			slog.Error("outbox relay", "err", err)
		}
	}
}

	switch {
	case now.After(c.ExpiresAt):

Step 4: The Go service review checklist

  • Clear boundary: it owns its data, and other services use its API or events.
  • Domain rules live in the domain package as plain methods, with unit tests.
  • Interfaces (ports) are defined by the consumer, small, and implemented by adapters.
  • main only wires things together. No globals, no init side effects.
  • ctx is passed everywhere, with timeouts on every outbound call.
  • Errors are wrapped with context and mapped once at the edge, and internals aren't leaked to clients.
  • Input is validated, body sizes are limited, and every query is parameterized.
  • AuthN in middleware, AuthZ in the service (and queries scoped by owner).
  • Idempotency for commands, dedup for consumed events, and an outbox for published events.
  • Server timeouts + graceful shutdown + separate readiness and liveness.
  • slog JSON logs with request and trace IDs, RED metrics, OTel traces.
  • Tests: unit, handler (httptest), integration (Testcontainers), with -race in CI.
  • golangci-lint, govulncheck and buf breaking in CI. Migrations are backward-compatible.
  • Distroless image, non-root, GOMEMLIMIT set, resources and probes defined.

2. inventory: reservations that never oversell

CREATE TABLE stock (
  sku        text PRIMARY KEY,
  on_hand    int NOT NULL CHECK (on_hand >= 0),
  reserved   int NOT NULL DEFAULT 0 CHECK (reserved >= 0),
  CHECK (reserved <= on_hand)              -- the database itself refuses to oversell
);
CREATE TABLE reservations (
  id          text PRIMARY KEY,           -- idempotency: Reserve twice → same row
  order_id    text NOT NULL,
  status      text NOT NULL,              -- HELD / COMMITTED / RELEASED
  expires_at  timestamptz NOT NULL,
  lines       jsonb NOT NULL
);
func (s *Service) Reserve(ctx context.Context, resID, orderID string, lines []Line, ttl time.Duration) ([]string, error) {
	var unavailable []string
	err := s.tx(ctx, func(q *db.Queries) error {
		existing, err := q.GetReservation(ctx, resID)
		if err == nil && existing.Status == "HELD" {
			return nil // idempotent retry → already reserved
		}
		// lock rows in a DETERMINISTIC order (sorted SKUs) → no deadlocks between concurrent checkouts
		slices.SortFunc(lines, func(a, b Line) int { return strings.Compare(a.SKU, b.SKU) })
		for _, l := range lines {
			n, err := q.ReserveStock(ctx, db.ReserveStockParams{Sku: l.SKU, Qty: l.Qty})
			// UPDATE stock SET reserved = reserved + $2 WHERE sku = $1 AND on_hand - reserved >= $2
			if err != nil {
				return err
			}
			if n == 0 {
				unavailable = append(unavailable, l.SKU)
			}
		}
		if len(unavailable) > 0 {
			return errRollback // undo the partial reservations in this transaction
		}
		return q.InsertReservation(ctx, db.InsertReservationParams{
			ID: resID, OrderID: orderID, Status: "HELD", ExpiresAt: s.now().Add(ttl), Lines: mustJSON(lines)})
	})
	if errors.Is(err, errRollback) {
		return unavailable, nil
	}
	return unavailable, err
}

type Checkout struct {
	repo      Repository      // orders + outbox, same DB
	pricing   PricingClient   // gRPC
	inventory InventoryClient // gRPC
	payments  PaymentsClient  // gRPC
	ids       func() string
	now       func() time.Time
}

func (c *Checkout) PlaceOrder(ctx context.Context, in PlaceOrderInput) (*Order, error) {
	// 0) idempotency: same key → same order (the client may retry on a timeout)
	if o, err := c.repo.ByIdempotencyKey(ctx, in.CustomerID, in.IdempotencyKey); err == nil {
		return o, nil
	}

	// 1) price the cart on the server (NEVER trust client prices)
	quote, err := c.pricing.Quote(ctx, in.CartID, in.CouponCode, in.AddressID)
	if err != nil {
		return nil, fmt.Errorf("quote: %w", err)
	}

	o := NewOrder(c.ids(), in.CustomerID, in.IdempotencyKey, quote, c.now()) // status PENDING
	if err := c.repo.Create(ctx, o, Event("OrderPlaced", o)); err != nil {   // order + outbox in ONE tx
		return nil, err
	}

	// 2) reserve stock (with a TTL so abandoned checkouts free the stock)
	unavailable, err := c.inventory.Reserve(ctx, o.ID, o.ID, o.Lines(), 15*time.Minute)
	if err != nil || len(unavailable) > 0 {
		c.fail(ctx, o, "out of stock", unavailable) // compensation: cancel the order (+ OrderCancelled event)
		if err != nil {
			return nil, err
		}
		return nil, &OutOfStockError{SKUs: unavailable}
	}

	// 3) create the payment intent; the client confirms it with the provider SDK
	intent, err := c.payments.CreateIntent(ctx, o.ID, o.TotalCents, o.Currency, in.IdempotencyKey)
	if err != nil {
		c.inventory.Release(context.WithoutCancel(ctx), o.ID) // compensate even if the request was cancelled
		c.fail(ctx, o, "payment init failed", nil)
		return nil, fmt.Errorf("create intent: %w", err)
	}
	o.PaymentClientSecret = intent.ClientSecret
	return o, nil
}

// Called by the Kafka consumer for payments.payment-events (idempotent by eventId).
func (c *Checkout) OnPaymentSucceeded(ctx context.Context, orderID string) error {
	o, err := c.repo.Get(ctx, orderID)
	if err != nil {
		return err
	}
	if err := o.MarkPaid(c.now()); err != nil { // the state machine refuses illegal transitions
		return nil // e.g. already PAID → duplicate event, ignore
	}
	if err := c.inventory.Commit(ctx, o.ID); err != nil {
		return err // retried by the consumer
	}
	return c.repo.Update(ctx, o, Event("OrderConfirmed", o)) // → notifications, shipping, merchants
}

type Inventory struct {
	mu       sync.Mutex
	stock    map[string]int
	reserved map[string]map[string]int // reservationID → sku → qty
}

func (inv *Inventory) Reserve(resID string, lines map[string]int) []string {
	inv.mu.Lock()
	defer inv.mu.Unlock()
	if _, done := inv.reserved[resID]; done {
		return nil // idempotent
	}
	var missing []string
	for sku, q := range lines {
		if inv.stock[sku] < q {
			missing = append(missing, sku)
		}
	}
	if len(missing) > 0 {
		slices.Sort(missing)
		return missing
	}
	for sku, q := range lines {
		inv.stock[sku] -= q
	}
	inv.reserved[resID] = lines
	return nil
}

func (inv *Inventory) Release(resID string) {
	inv.mu.Lock()
	defer inv.mu.Unlock()
	for sku, q := range inv.reserved[resID] {
		inv.stock[sku] += q
	}
	delete(inv.reserved, resID)
}

func Checkout(o *Order, inv *Inventory, pay Payments) {

		o.step("payment failed (" + err.Error() + ") → stock released")
		return
	}
	o.step("payment captured")
	o.Status = "CONFIRMED"
}

package main

import (
	"errors"
	"fmt"
	"time"
)

type Status string

const (
	Created   Status = "CREATED"
	Paid      Status = "PAID"
	Accepted  Status = "ACCEPTED"
	Preparing Status = "PREPARING"
	Ready     Status = "READY"
	PickedUp  Status = "PICKED_UP"
	Delivered Status = "DELIVERED"
	Cancelled Status = "CANCELLED"
)

// allowed transitions: the single source of truth for the lifecycle
var transitions = map[Status][]Status{
	Created:   {Paid, Cancelled},
	Paid:      {Accepted, Cancelled},
	Accepted:  {Preparing, Cancelled},
	Preparing: {Ready, Cancelled},
	Ready:     {PickedUp},
	PickedUp:  {Delivered},
}

var ErrIllegalTransition = errors.New("illegal transition")

type Order struct {
	ID      string
	Status  Status
	Version int // optimistic locking: UPDATE … WHERE id=$1 AND version=$2
	History []string
}

func (o *Order) Transition(to Status, at time.Time, reason string) error {
	for _, allowed := range transitions[o.Status] {
		if allowed == to {
			o.History = append(o.History, fmt.Sprintf("%s→%s (%s)", o.Status, to, reason))
			o.Status = to
			o.Version++
			return nil
		}
	}
	return fmt.Errorf("%w: %s → %s", ErrIllegalTransition, o.Status, to)
}

func main() {
	now := time.Now()
	o := &Order{ID: "f-1001", Status: Created}
	steps := []struct {
		to     Status
		reason string
	}{
		{Paid, "payment webhook"}, {Accepted, "restaurant tablet"}, {Preparing, "kitchen"},
		{Ready, "kitchen"}, {Delivered, "BUG: skipped pickup"}, {PickedUp, "rider app"}, {Delivered, "rider app"},
	}
	for _, s := range steps {
		if err := o.Transition(s.to, now, s.reason); err != nil {
			fmt.Println("rejected:", err)
		}
	}
	fmt.Println("final:", o.Status, "version:", o.Version)
	for _, h := range o.History {
		fmt.Println(" ", h)
	}
	fmt.Println(o.Transition(Cancelled, now, "too late") != nil) // can't cancel a delivered order
}

func (s *Server) StreamLocation(stream grpc.ClientStreamingServer[locationv1.LocationPing, locationv1.StreamAck]) error {
	riderID := auth.RiderFrom(stream.Context()) // from the mTLS cert or the token, never trust the payload's rider_id
	var n int64
	for {
		p, err := stream.Recv()
		if errors.Is(err, io.EOF) {
			return stream.SendAndClose(&locationv1.StreamAck{Received: n})
		}
		if err != nil {
			return err
		}
		if !plausible(p) { // drop GPS jumps (100 km in 3 s) and stale timestamps
			continue
		}
		n++
		city := s.cities.Resolve(p.Lat, p.Lng)
		// 1) hot state: Redis GEO set per city, used for "nearby riders"
		s.rdb.GeoAdd(stream.Context(), "riders:geo:"+city, &redis.GeoLocation{Name: riderID, Longitude: p.Lng, Latitude: p.Lat})
		s.rdb.Set(stream.Context(), "rider:last:"+riderID, encode(p), 2*time.Minute) // expires → considered offline
		// 2) stream for consumers (tracking fan-out, analytics, ETA learning)
		s.producer.Produce(stream.Context(), &kgo.Record{Topic: "rider.location", Key: []byte(riderID), Value: encode(p)}, nil)
	}
}

4. Dispatch: matching riders to orders (runnable simulation)

The real system scores candidates by distance, ETA to the restaurant vs food-ready time, rider rating, acceptance rate, current load (batching two orders), and fairness. Offers go out one rider at a time (or in parallel waves), with a timeout.

package main

import (
	"cmp"
	"fmt"
	"math"
	"slices"
	"time"
)

type Point struct{ Lat, Lng float64 }

// Haversine distance in km (great-circle)
func DistanceKm(a, b Point) float64 {
	const R = 6371.0
	rad := func(d float64) float64 { return d * math.Pi / 180 }
	dLat, dLng := rad(b.Lat-a.Lat), rad(b.Lng-a.Lng)
	h := math.Sin(dLat/2)*math.Sin(dLat/2) + math.Cos(rad(a.Lat))*math.Cos(rad(b.Lat))*math.Sin(dLng/2)*math.Sin(dLng/2)
	return 2 * R * math.Asin(math.Sqrt(h))
}

type Rider struct {
	ID         string
	Pos        Point
	Rating     float64 // 1..5
	ActiveJobs int
	AcceptRate float64 // 0..1
}

type Job struct {
	OrderID    string
	Restaurant Point
	FoodReady  time.Duration // from now
}

const avgSpeedKmh = 20.0

func travel(km float64) time.Duration { return time.Duration(km / avgSpeedKmh * float64(time.Hour)) }

// score: lower is better. Ideal = arrive exactly when the food is ready.
func score(r Rider, j Job) float64 {
	arrive := travel(DistanceKm(r.Pos, j.Restaurant))
	wait := math.Abs((arrive - j.FoodReady).Minutes()) // early → rider waits; late → food gets cold
	return wait*1.0 + float64(r.ActiveJobs)*4 + (5-r.Rating)*2 + (1-r.AcceptRate)*5
}

type Offer func(r Rider, j Job) bool // returns true if the rider accepted within the timeout

func Dispatch(j Job, riders []Rider, radiusKm float64, offer Offer) (string, []string) {
	var cands []Rider
	for _, r := range riders {
		if DistanceKm(r.Pos, j.Restaurant) <= radiusKm && r.ActiveJobs < 2 {
			cands = append(cands, r)
		}
	}
	slices.SortFunc(cands, func(a, b Rider) int { return cmp.Compare(score(a, j), score(b, j)) })
	var log []string
	for _, r := range cands { // sequential offers (production: waves + 15s timeouts)
		ok := offer(r, j)
		log = append(log, fmt.Sprintf("offer→%s (%.2f km, score %.1f): %v",
			r.ID, DistanceKm(r.Pos, j.Restaurant), score(r, j), ok))
		if ok {
			return r.ID, log
		}
	}
	return "", append(log, "no rider found → widen the radius / surge / alert ops")
}

	sel.Select(ctx)

	}
	_ = workflow.ExecuteActivity(ctx, RequestDispatch, o).Get(ctx, nil)

	return workflow.ExecuteActivity(ctx, CapturePayment, auth).Get(ctx, nil)

	p, ok := c.cache[id]
	c.mu.RUnlock()
	if ok {
		return p, nil
	}
	p, err := c.next.Get(ctx, id)
	if err == nil {
		c.mu.Lock()
		c.cache[id] = p
		c.mu.Unlock()
	}
	return p, err
}

The idioms checklist (what reviewers look for)

  • Early returns; the happy path is left-aligned. No deep nesting or else after a return.
  • Accept interfaces, return structs. Interfaces are small and defined by the consumer.
  • The zero value is useful (var b bytes.Buffer works).

cgo & unsafe

  • cgo calls C from Go. It costs ~50–100 ns per call, breaks static binaries and cross-compilation, and complicates builds (CGO_ENABLED=0 is the default for containers). Prefer pure-Go libraries (e.g. modernc.org/sqlite).

  • Struct padding matters at scale: order fields from largest to smallest (fieldalignment linter) to shrink structs.

System design in Go: how SDE-3 interviews and design docs work

At the senior level the code is the easy part. You're judged on clarifying requirements, estimating scale, choosing trade-offs, and explaining failure modes. Use this framework every time.

The 7-step framework

  1. Clarify: functional scope, users, read/write ratio, consistency needs, latency and availability targets. Say what is out of scope.
  2. Estimate: QPS, storage and bandwidth. (1M DAU × 10 actions/day ≈ 115 QPS average, peak ~5×.)
  3. API: the main endpoints or RPCs, and the events.
  4. Data model: entities, keys, indexes, and the choice of store (SQL vs KV vs wide-column vs search) with reasons.
  5. High-level design: boxes and arrows, request flow, sync vs async.
  6. Deep dive: the 1–2 hardest parts (hot keys, ordering, consistency, fan-out).
  7. Reliability & trade-offs: failure modes, scaling, observability, what you'd do next.

package main

import (
	"errors"
	"fmt"
	"net/http"
	"net/http/httptest"
	"strings"
	"sync"
	"sync/atomic"
)

const alphabet = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"

func Base62(n uint64) string {
	if n == 0 {
		return "0"
	}
	var b []byte
	for ; n > 0; n /= 62 {
		b = append(b, alphabet[n%62])
	}
	for i, j := 0, len(b)-1; i < j; i, j = i+1, j-1 {
		b[i], b[j] = b[j], b[i]
	}
	return string(b)
}

// IDRange: each instance leases a block of IDs from a central store (e.g. 1000 at a time),
// then hands them out locally with an atomic counter: no per-request coordination.
type IDRange struct{ next, end atomic.Uint64 }

var ErrExhausted = errors.New("id range exhausted: lease a new block")

func (r *IDRange) Next() (uint64, error) {
	id := r.next.Add(1) - 1
	if id >= r.end.Load() {
		return 0, ErrExhausted
	}
	return id, nil
}

type Shortener struct {
	mu    sync.RWMutex
	urls  map[string]string
	ids   *IDRange
	clicks atomic.Int64
}

func (s *Shortener) Create(long string) (string, error) {
	if !strings.HasPrefix(long, "http://") && !strings.HasPrefix(long, "https://") {
		return "", errors.New("only http(s) URLs") // also block internal hosts in real life (SSRF)
	}
	id, err := s.ids.Next()
	if err != nil {
		return "", err
	}
	code := Base62(1_000_000_000 + id) // offset so codes are ≥ 6 chars and not trivially guessable
	s.mu.Lock()
	s.urls[code] = long
	s.mu.Unlock()
	return code, nil
}

func (s *Shortener) Handler() http.Handler {
	mux := http.NewServeMux()
	mux.HandleFunc("POST /links", func(w http.ResponseWriter, r *http.Request) {
		code, err := s.Create(r.FormValue("url"))
		if err != nil {
			http.Error(w, err.Error(), http.StatusBadRequest)
			return
		}
		fmt.Fprintf(w, "/%s", code)
	})
	mux.HandleFunc("GET /{code}", func(w http.ResponseWriter, r *http.Request) {
		s.mu.RLock()
		long, ok := s.urls[r.PathValue("code")]
		s.mu.RUnlock()
		if !ok {
			http.NotFound(w, r)
			return
		}
		s.clicks.Add(1) // production: async event, not inline
		http.Redirect(w, r, long, http.StatusFound)
	})
	return mux
}

func main() {
	s := &Shortener{urls: map[string]string{}, ids: &IDRange{}}
	s.ids.next.Store(1)
	s.ids.end.Store(1001)
	srv := httptest.NewServer(s.Handler())
	defer srv.Close()

	client := &http.Client{CheckRedirect: func(*http.Request, []*http.Request) error { return http.ErrUseLastResponse }}
	res, _ := http.PostForm(srv.URL+"/links", map[string][]string{"url": {"https://go.dev/doc"}})
	buf := new(strings.Builder)
	b := make([]byte, 64)
	n, _ := res.Body.Read(b)
	buf.Write(b[:n])
	path := buf.String()
	fmt.Println("short path:", path)
	res2, _ := client.Get(srv.URL + path)
	fmt.Println("redirect:", res2.StatusCode, res2.Header.Get("Location"))
}

Interview prep: 70 questions across the whole stack

Answer out loud first, then open each one. They progress from the language to systems.

Language fundamentals

1. Arrays vs slices?
An array has a fixed length that's part of its type and is copied on assignment. A slice is a header (pointer, len, cap) over a backing array. Slices share memory, and append may reallocate.
2. What happens on append when capacity is exceeded?
A new, larger backing array is allocated (roughly 2× for small slices, ~1.25× for large ones), the elements are copied, and the new slice header points to it. Old references still see the old array.
3. Why is map iteration order random? Are maps goroutine-safe?
The order is deliberately randomized so programs don't depend on it. Maps are not safe for concurrent writes (the runtime detects and crashes). Use a mutex, sync.Map, or sharding.
4. Value vs pointer receivers?
Pointer receivers can mutate, avoid copying, and are required for types with mutexes. Value receivers suit small immutable types. Be consistent per type. Method sets: T has value methods, *T has both.
5. How do interfaces work internally? What's the nil-interface trap?
An interface value is (type, data pointer). It equals nil only when both are nil. A typed nil pointer in an interface is non-nil, so returning a nil *MyErr as error makes err != nil true.
6. defer: order, argument evaluation, loop pitfalls?
Deferred calls run LIFO at function return. Arguments are evaluated at the defer statement. In a loop, defers pile up until the function returns, so extract a helper.
7. panic/recover: when to use?
Panics for unrecoverable programmer errors. recover works only inside deferred functions, and is used at boundaries (HTTP middleware, goroutine entry points) to avoid crashing the process. Libraries should return errors.
8. new vs make?
new(T) returns a pointer to a zeroed T. make initializes slices, maps and channels and returns the value.
9. What are generics good for, and what are their limits?
Containers, algorithms over slices and maps, and typed utilities without any. Limits: no methods with their own type parameters, constraints via interfaces, and over-abstraction hurts readability.
10. How does Go handle errors, and how do you inspect them?
Errors are values. Wrap with fmt.Errorf("…: %w", err). Inspect with errors.Is (value in the chain) and errors.As (type in the chain). errors.Join combines several.
11. What does the loop variable change in Go 1.22 do?
Each iteration gets a new variable, so closures and goroutines capturing it no longer all see the last value.
12. Strings, bytes, runes?
Strings are immutable byte sequences (UTF-8 by convention). len is bytes. range over a string yields runes. Use strings.Builder for concatenation.

Concurrency

13. Goroutine vs OS thread?
Goroutines are user-space tasks with small, growable stacks, multiplexed by the Go scheduler onto few OS threads. Creating one is cheap (KBs), so hundreds of thousands are feasible.
14. Explain the G-M-P scheduler.
G = goroutine, M = OS thread, P = processor context holding a local run queue. An M needs a P to run Go code. Idle Ps steal work. Blocking syscalls hand the P to another M. The netpoller parks goroutines waiting for I/O.
15. Buffered vs unbuffered channels? What happens on nil and closed channels?
Unbuffered: a send blocks until a receive (synchronization). Buffered: blocks only when full. Nil channels block forever. Receiving from closed returns zero + ok=false. Sending on closed or closing twice panics.
16. How do you stop a goroutine?
Cooperatively: a context cancellation, a done channel, or closing the input channel. Goroutines can't be killed from outside.
17. Mutex vs channel?
Channels for ownership transfer and pipelines. Mutexes for protecting shared state. Prefer whichever is simpler to reason about.
18. What is a data race, and how do you find it?
Unsynchronized concurrent access where at least one is a write. Run tests with -race. Fix with a mutex, atomics or channels.
19. What causes goroutine leaks? How do you detect them?
Goroutines blocked forever on channel ops, locks or I/O without a cancellation path. Detect with pprof goroutine profiles, goleak in tests, and monitoring runtime.NumGoroutine.
20. Design a worker pool with graceful shutdown.
A jobs channel, N workers ranging over it, a WaitGroup, a producer that closes the channel on completion or ctx cancel, workers that check ctx between tasks, and results collected through a channel closed after wg.Wait().
21. What is context for, and what are the rules?
Cancellation, deadlines and request-scoped values across API boundaries. First parameter, never stored in structs, always defer cancel(), values only for request-scoped metadata.
22. sync.WaitGroup, Once, Pool, atomic: when to use?
WaitGroup: wait for N goroutines. Once: one-time init. Pool: reuse temporary objects to cut GC pressure. Atomic: lock-free counters and flags. RWMutex: read-mostly shared state.
23. How do you do fan-out/fan-in with bounded parallelism?
Spawn workers reading from a shared channel (fan-out) and merge results into one channel (fan-in), or use errgroup.SetLimit. A semaphore channel also bounds in-flight work.
24. How do you handle a cache stampede?
singleflight to collapse concurrent loads for one key, TTL jitter, early refresh, and serving stale-while-revalidate.

Runtime & performance

25. How does Go's garbage collector work?
A concurrent tri-color mark-and-sweep, non-generational and non-moving, with write barriers. Short stop-the-world phases. Cost scales with the live heap and allocation rate. Tuned by GOGC and GOMEMLIMIT.
26. How do you find and fix a memory leak?
Compare heap profiles over time (pprof -base), check goroutine counts, look for unbounded maps/caches, global slices, unclosed bodies and tickers, and subslices pinning large arrays.
27. Stack vs heap allocation? Escape analysis?
The compiler keeps values on the stack when they don't outlive the function. Values that escape (returned pointers, stored in interfaces, captured by closures, too large) go to the heap. Inspect with -gcflags=-m.
28. How would you optimize a slow endpoint?
Measure (traces, pprof, DB EXPLAIN). Fix I/O and algorithmic problems first (N+1, missing indexes, serial calls that could run in parallel, caching). Then reduce allocations in proven hot paths. Verify with benchmarks and load tests.
29. What's GOMEMLIMIT and why does it matter in containers?
A soft memory limit for the runtime: the GC becomes more aggressive near it. Setting it near ~90% of the container limit avoids OOM kills. (GOMAXPROCS also respects container CPU limits since Go 1.25.)
30. How do you benchmark correctly?
Use testing.B (b.Loop), -benchmem, multiple runs, and benchstat. Avoid dead-code elimination, use realistic inputs, and compare before and after.

Backend & databases

31. How do you structure a Go service?
Domain + app (use cases with ports) + adapters (HTTP, gRPC, Postgres, Kafka), with main wiring dependencies by hand, internal/ to enforce boundaries, and tests per layer.
32. What timeouts must an HTTP server and client set?
Server: ReadHeaderTimeout, ReadTimeout, WriteTimeout, IdleTimeout. Client: Client.Timeout plus per-request contexts and transport pool limits. The defaults are "no timeout".
33. Graceful shutdown in Go?
signal.NotifyContext for SIGTERM, flip readiness to false, srv.Shutdown(ctx) with a deadline, stop consumers and flush producers, close DB pools, and keep the process alive until in-flight work ends.
34. How do you avoid SQL injection and N+1?
Parameterized queries (never string concatenation), allow-lists for identifiers. For N+1, use JOINs, batch queries with ANY($1), or dataloaders.
35. How do you prevent overselling stock?
An atomic conditional update (… WHERE available >= qty) or SELECT FOR UPDATE, DB CHECK constraints, reservations with TTL, deterministic lock ordering, and idempotency on retries.
36. Optimistic vs pessimistic locking?
Optimistic: a version column and UPDATE … WHERE version=$n, retry on conflict (low contention). Pessimistic: row locks (FOR UPDATE) for high contention or when retries are costly.
37. Cache-aside vs write-through? Invalidation strategies?
Cache-aside: the app reads the cache and falls back to the DB. Write-through: writes go through the cache. Invalidate by TTL, delete-on-write, versioned keys or event-driven invalidation.
38. JWT vs sessions?
JWTs are stateless and verifiable by every service, but hard to revoke (use short lifetimes + refresh rotation). Sessions are easy to revoke and simple, but need a shared store.
39. How do you secure webhooks you receive and send?
HMAC signatures over timestamp + raw body, constant-time compare, replay window, event IDs + dedup, acknowledge fast and process async; when sending: retries with backoff, SSRF protections, a dead-letter state.
40. Idempotency: how do you implement it for POST?
A client-supplied Idempotency-Key stored with the response (scoped per caller). Replays return the original response, concurrent duplicates get 409. Back it with a unique DB constraint.

API styles

41. REST vs gRPC vs GraphQL: how do you choose?
REST for public, cacheable APIs. gRPC for internal service calls (typed, fast, streaming, deadlines). GraphQL for client-driven aggregation (a BFF). Real systems mix them.
42. How do you evolve a REST API without breaking clients?
Additive changes only within a version, tolerant readers, deprecation windows, version in the path or header for breaking changes, and contract tests.
43. What is the N+1 problem in GraphQL, and the fix?
Resolvers per item cause one backend call each. Use a dataloader to batch and cache per request, and add complexity and depth limits.
44. Protobuf compatibility rules?
Never reuse or renumber fields, add new fields with new numbers, mark removals as reserved, don't change types. Enforce with buf breaking.
45. gRPC streaming types and use cases?
Server streaming (feeds, order updates), client streaming (uploads, GPS pings), bidirectional (chat). Handle cancellation through the stream context.
46. WebSocket vs SSE?
WebSocket is bidirectional and needs its own reconnect logic. SSE is server-to-client over plain HTTP with built-in reconnection. SSE suffices for most notifications and status feeds.
47. How do you scale WebSockets horizontally?
Stateless gateway pods holding local connections, a pub/sub backbone (Redis/NATS) so any pod can deliver to any user, heartbeats, resume tokens, and LB idle timeouts longer than the ping interval.
48. How does a typical gRPC deadline propagate?
The client sets a deadline in the context. gRPC sends it as metadata, and the server's context expires at the same time. The server passes ctx to downstream calls so the whole chain is bounded.

Microservices & distributed systems

49. Monolith vs microservices: when do you split?
Start with a modular monolith. Split when independent scaling or deployment, team autonomy or fault isolation outweigh the operational cost, and along bounded contexts with their own data.
50. Saga: choreography vs orchestration?
Choreography: services react to events (decoupled, harder to trace). Orchestration: a coordinator (or Temporal) drives steps and compensations (explicit, centralized). Both need idempotent steps and timeouts.
51. Explain the outbox pattern.
Write the business change and the event in one DB transaction. A relay (CDC or a poller with SKIP LOCKED) publishes it to the broker, so there are no lost or phantom events (at-least-once, deduped by consumers).
52. Exactly-once delivery: is it possible?
Not end to end in general. You get effectively-once by combining at-least-once delivery with idempotent processing (dedup by event ID, natural idempotency), or Kafka transactions within Kafka.
53. Circuit breaker, retries, bulkheads: how do they fit together?
Timeouts bound each call. Retries with backoff + jitter handle transient errors (one layer only, idempotent ops). Breakers stop hammering a failing dependency. Bulkheads isolate resource pools. Fallbacks degrade gracefully.
54. How do you handle distributed tracing across services?
Propagate W3C traceparent through HTTP/gRPC/Kafka headers (OpenTelemetry), create spans per operation, link logs with trace IDs, and sample sensibly.
55. How do services find and call each other on Kubernetes?
Kubernetes Services + CoreDNS (svc.ns.svc.cluster.local), client-side load balancing for gRPC (headless service or xDS), plus a mesh when you need mTLS and traffic policy.
56. How do you do zero-downtime deployments and migrations?
Rolling updates with readiness probes and graceful shutdown, backward-compatible schema changes (expand → migrate → contract), feature flags, and canary releases with automated rollback.
57. How do you design for multi-tenancy?
A tenant ID in every table and query (or schema/DB per tenant for isolation), tenant-scoped auth claims, per-tenant rate limits and quotas, noisy-neighbour protection, and tenant-aware partitioning.
58. CAP theorem in practice?
Under a network partition you choose consistency (reject requests) or availability (serve possibly stale data). Money and inventory lean to CP for the critical write; feeds and caches lean AP.

Project & design questions

59. Design the checkout of an e-commerce platform.
An orders service with an idempotent API, server-side pricing, inventory reservations with a TTL, a payment intent confirmed through a signed webhook, a saga with compensation (release stock, refund), outbox events to notifications and shipping, an SSE status feed, and reconciliation. (Level 9.)
60. Design the rider tracking and dispatch for food delivery.
Riders stream GPS over gRPC/WebSocket into a location service (Redis GEO per city + Kafka). Dispatch queries nearby riders, scores by ETA vs food-ready time and load, and sends timed offers with conditional assignment. Tracking fans out per-order channels to WebSocket gateways. (Level 10.)
61. Design a rate limiter for an API gateway.
A token bucket per key. Local limiter first, a global counter in Redis via a Lua script (atomic), sliding-window for fairness, return 429 + Retry-After, and fail-open or closed by policy.
62. Design a notification system.
Events into Kafka, a router applying user preferences and templates, per-channel workers (email, SMS, push) with retries and a DLQ, provider failover, dedup keys, a delivery log, and rate limits per user.
63. Design a search-as-you-type feature.
An index in OpenSearch or a trie service fed by catalog events, caching of hot prefixes, debounced client requests, ranking with popularity, and a degraded fallback to cached suggestions.
64. How would you migrate a monolith to microservices?
The strangler pattern: put a gateway in front, extract one bounded context at a time (start with edges like notifications), replicate its data through CDC or events, switch traffic gradually with flags, then delete the old code. Avoid a big-bang rewrite.
65. A service's p99 latency doubled after a deploy. Walk me through it.
Check dashboards and what changed (deploy diff, config, traffic). Use traces to find the slow span, check downstream dependencies and DB metrics, CPU throttling, GC pauses and goroutine counts, and compare pprof profiles. Roll back first if it's user-impacting, then root-cause.
66. How do you make a Go service observable?
slog JSON logs with request and trace IDs, RED metrics via Prometheus (low-cardinality labels), OpenTelemetry traces, pprof on an internal port, health endpoints, and SLO-based alerts with runbooks.
67. How do you test a service with many dependencies?
Unit tests on domain rules, service tests with fakes behind interfaces, handler tests with httptest, integration tests with Testcontainers, contract tests for protos and OpenAPI, and a few end-to-end tests. Always run -race.
68. How do you decide between Go and another language?
Go fits networked services, infrastructure, CLIs and high concurrency with simple operations. Pick Python for ML and data science, Rust for the tightest performance and memory control, and Java/Kotlin where the JVM ecosystem is required. Team skills matter.
69. What would you improve in a codebase you inherited?
Add tests around critical paths first, enable linters and race detection, set timeouts, add structured logging and tracing, break up giant packages along domain boundaries, replace global state with injected dependencies, and document the decisions.
70. Tell me about a hard technical decision and its trade-offs.
Use a structure: context and constraints → options considered → criteria → decision and why → what you gave up → how you validated (metrics, rollout) → what you'd do differently. SDE-3 interviews score the reasoning, not just the outcome.
